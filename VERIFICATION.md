### Defects found and fixed by these tests

1. **linfa-logistic positive class** (found by the closed-form baseline). The crate
   documents "probability of the larger class" but `label_classes` selects the class
   with the larger *count* (ties: first encountered). The adapter now reads
   `labels().pos.class` and negates coefficients when class 0 was modelled.
2. **Dummy column order** (found by the differential suite). recipes appends indicator
   columns after the remaining columns; the first implementation inserted them in
   place. Fixed; feature order is now compared exactly.
3. **Rank-deficient folds** (found by the differential suite on Ames). A dummy level
   absent from a fold's analysis rows yields an all-zero column; linfa's least squares
   errors ("Matrix is non-invertible") where R pivots and reports `NA`. The framework now
   drops identically-zero columns, and constant columns when an intercept is fitted,
   before calling any backend, reports them in `FitDiagnostics::aliased`, and assigns
   coefficient 0, which reproduces R's predictions (ADR-0007).

Interpretation:

- Preprocessing and OLS agree to floating-point round-off (1e-13 relative and better);
  these are *numerical parity* in the sense of docs/specs/verification-design.md.
- Logistic regression agrees to ~1e-8 relative. This is *semantic parity with a
  solver bound*: same objective (binomial MLE), different optimizer (IRLS vs L-BFGS).
  The bound is set by R's deviance tolerance (1e-8) and our gradient tolerance; it is
  not a defect. The tolerance file was tightened to 1e-7 after this measurement.
- R emitted "prediction from rank-deficient fit" in one Ames fold; the framework's
  aliasing rule reproduced R's per-fold metrics to 1e-15 relative on that fold.
- `glm` converged in 5–8 IRLS iterations on every classification task; both Rust engines
  reported `converged = true` by the framework gradient check.

Triage of all out-of-tolerance differences: none occurred.

Findings while porting: (1) `stats::weighted.mean` computes `sum((x * w)[w != 0]) / sum(w)`,
so an `NA` with zero weight is dropped even without `na.rm`; this is why `macro_weighted`
survives an absent level while `macro` does not, and the port reproduces it. (2)
`bal_accuracy_table_impl` averages without `na.rm` while `sens`/`spec`/`j_index`/`f_meas`
use `na.rm = TRUE`; the fixture with an absent level distinguishes the two. (3)
yardstick's `pr_auc` with no events is `NaN` (jsonlite writes `null`); it is `None` here.

The Python entry points `class_metrics` and `conf_mat` are checked against the same
fixture in `python/tests/test_parity.py` (36 tests pass).

Not covered: case weights, `roc_curve(thresholds =)`, multiclass metrics on model
predictions (no multiclass model yet; Phase 8c), and yardstick's warnings (silent here).
