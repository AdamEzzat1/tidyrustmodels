# tidyrustmodels 0.1.0 — release notes (candidate)

Status: **release candidate, not tagged.** Two gates of the 0.1.0 milestone are still
open (ROADMAP.md Phase 6): an independent reviewer's sign-off, and the Linux / macOS
builds that CI defines but has not yet executed. Everything below is verified on
Windows 11 only.

## What it is

A Rust-native machine learning framework with tidymodels semantics: recipes that
prep on training rows and bake anywhere, model specifications independent of the
backend that fits them, leakage-safe resampling with rsample's schemes, yardstick's
metrics, grid tuning with tune's selection rules, workflow sets, and a Python package
that returns bitwise the same numbers as the Rust API.

## What is verified

Every feature with an R counterpart was compared with R tidymodels output on
committed fixtures (VERIFICATION.md). The differential suite holds 17 541
comparisons over 70 reference tasks with zero failures under the committed
tolerances; the tolerance file records measured maxima, never relaxed bounds.

| area | agreement with R |
|---|---|
| recipes steps (12) | round-off (1e-11 or better) |
| `lm`, `glm` (`native` engine) | round-off (3e-13 rel), incl. R's aliased-coefficient choice |
| `nnet` multinomial | to nnet's own convergence residual |
| rpart trees | exact, node for node |
| ranger forests | statistical (4-SE bands over 10 seeds per side) |
| xgboost boosters | exact tree structure, values at float32 rounding |
| rsample schemes | ids exact; deterministic schemes exact; metrics on shared rsets exact |
| yardstick metrics (23, case-weighted too) | round-off |
| tune selection, `last_fit`, `fit_best` | exact |
| workflowsets | exact up to R's random tie ranks |

Independent of R: exact rational OLS and closed-form logistic baselines, serial ==
parallel, JSON round trips, Python == Rust bitwise.

## What is measured

BENCHMARKS.md records every number with its run id, environment and the protocol
deviations of that run. In summary, on one Windows laptop against R tidymodels with
single-threaded reference BLAS (protocol run G, 2026-10-13: 10 cold trials, 30 warm
iterations, 10 folds, 20-point grids): linear and logistic workflows with the native
engine fit 12–930× faster than R per workflow fit (930× at 342 rows, 12× at 100k) and
run 10-fold CV 7.5–2200× faster; the native IRLS is about 4× `glm` in steady state at
1e5 rows; logistic tuning is 2.5× glmnet at 10k rows. Peak memory is reported for
every row. Tree, forest and boosting workflows, case weights, the resampling schemes,
tuning selection, workflow sets and the 1e6-row point have drivers and tasks but their
protocol runs (I, J, K, H) are queued and **not yet on record**. No result from this
machine transfers to other hardware; the second-platform run is still open.

## Installation

Rust (from the repository; the crates are not yet on crates.io):

```toml
[dependencies]
tidyrustmodels = { git = "https://github.com/adamezzat/tidyrustmodels", package = "tidyrustmodels" }
# optional: features = ["arrow"]
```

Python 3.11+ (from source with maturin; wheels are built by the release workflow but
not yet published):

```
python -m venv .venv && . .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install maturin numpy
maturin develop --release                          # or: pip install .
```

Optional Python extras: `pandas`, `pyarrow`, `polars`, `scipy`.

## Examples

- Rust: `cargo run --release --example penguins_workflow` (classification end to end),
  `--example ames_tuning` (tree tuning, selection rules, `last_fit`, `fit_best`),
  `--example ames_workflow_sets` (preprocessors x models, ranking, refit).
- Python: `examples/penguins_workflow.py`, `examples/ames_tuning.py`,
  `examples/ames_workflow_sets.py`.

## Known limitations

See LIMITATIONS.md. The ones most likely to matter: no glmnet-equivalent penalties;
trees need dummy-encoded, complete predictors; forests are never R's forest (own
RNG); sparse data is a flag on dense storage; `rank_results` orders ties
deterministically; no Bayesian or racing search; unseen factor levels at bake time are
an error unless `step_novel` precedes `step_dummy`.
