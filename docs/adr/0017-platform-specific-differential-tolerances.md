# ADR-0017: Platform-specific differential tolerances

Date: 2026-10-14. Status: accepted.

## Context
The differential suite (`crates/tidyrustmodels/tests/differential.rs`) compares every
port against R fixtures (`reference/fixtures/r/*.json`) under per-quantity bounds in
`reference/fixtures/tolerances.toml`; bounds are set from measured maxima and never
relaxed silently (VERIFICATION.md). The fixtures were produced by R on Windows
(`versions.platform` = `x86_64-w64-mingw32`) and, until the repository was pushed to
GitHub on 2026-10-14, the suite had only ever run on that machine.

The first CI run on three platforms (run 38616615538, commit `578a958`, rustc 1.99.0)
passed every comparison on Windows and failed 5 of 17 542 on Linux x86_64
(ubuntu-24.04) and 17 on macOS arm64 (macos-26-arm64). Every failing row belongs to the
five xgboost *classification* tasks (`synth_clf_xgb`, `synth_multi_xgb`,
`penguins_species_xgb`, `synth_clf_xgb_wimp`, `synth_multi_xgb_wfreq`); the regression
boosters, every other model and every preprocessing quantity are identical on all
three platforms.

The mechanism: the boosting port mirrors xgboost's float32 arithmetic and calls
`f32::exp` / `f32::ln` in the sigmoid, the softmax and the base-score logit
(`crates/tidyrustmodels-models/src/native/xgb.rs`). Rust routes those to the C
runtime's `expf` / `logf`, which Windows UCRT, glibc and Apple's libm round
differently in the last ulp. R's xgboost does the same on its own platform, so on
Windows the two sides share one `expf` and agree bit for bit; on another platform the
port is compared with *Windows* `expf` results. The one-ulp difference in a gradient
is amplified by the gradient and hessian sums into the fold boosters' tree statistics
(loss changes, base weights, split values: up to 2.9e-5 relative) and, through the
per-fold metrics, into the CV summary mean and standard error (up to 1.4e-8 relative
against a 1e-12 bound). Predictions, probabilities and per-fold metrics stayed inside
the one-ulp bounds that `tolerances.toml` already granted them (assessment
probabilities ≤ 1.2e-7 absolute, fold metrics ≤ 4.2e-9 relative).

## Decision
1. `tolerances.toml` gains sections `[platform.<os>-<arch>.tasks.<task>]` that apply
   only when the test binary's `std::env::consts::{OS, ARCH}` match. The harness looks
   a key up in the platform section first, then the task section, then `[defaults]`.
   Sections for other platforms are parsed and dropped; any other section name is an
   error.
2. The bounds on the fixture platform (`windows-x86_64`) are unchanged: there the
   float32 mirror holds exactly and the suite keeps asserting it.
3. Platform sections set only the keys that a measured row needed (`xgb_tree_rel`,
   `native_summary_rel`, `native_summary_abs` on the classification boosting tasks),
   each to the maximum measured on the named runner image, rounded up to two
   significant digits, with the measured maximum quoted beside it. The ulp-class bounds
   that already held are not widened.
4. The report (`target/differential_report.md`) starts with the running platform, the
   fixtures' R platform and the number of platform-specific bounds in force, so no
   report is read without knowing which bounds applied. CI uploads the report as an
   artifact.
5. The claim "bit-exact against xgboost" is stated as holding on the fixture platform.
   Whether the port is bit-exact against an xgboost built on Linux or macOS is **not
   measured**: that needs fixtures generated by R on those platforms (ROADMAP.md).

## Consequences
- The suite is green on all three CI platforms with 3 (Linux) and 11 (macOS) bounds
  wider than on Windows, every one documented with its measurement.
- A new platform or a runner-image change with a different libm shows up as a
  failing row with the measured maximum, to be recorded the same way, never by
  widening a default.
- Any future use of `exp` / `ln` / `pow` in a float32 mirror must expect the same
  class of difference; a platform-independent `expf` (a correctly rounded or
  table-driven implementation) would remove it at the cost of no longer matching
  xgboost's own platform results, and was not chosen.

## Alternatives rejected
- Widening the task bounds for every platform: relaxes the Windows contract where the
  exact match is measured.
- Skipping the boosting classification rows off the fixture platform: loses the
  measurement that the deviation is bounded at the ulp level.
- Replacing `f32::exp` by a portable implementation: the port would then differ from
  xgboost on every platform instead of matching it on the one where the fixtures live.
